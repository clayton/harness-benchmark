# Studies and Callouts

| Goal | Command path |
|---|---|
| Test one setup on one scenario | `hbench setup save` → `hbench run --setup ID` → `hbench execute RUN_ID` → `hbench publish --preview RUN_ID` → `hbench publish RUN_ID` |
| Compare two or more setups | `hbench study init --setup ID --setup ID` → `validate` → `plan` → `run` → `report` → `publish` |
| Challenge a published claim | `hbench callout challenge URL` → run the downloaded Study |

Before either path, run `command -v hbench` and `hbench version`. To use an arbitrary local harness, create an `hb.adapter.v1` YAML manifest, validate it with `hbench adapter validate PATH`, then pass `--adapter PATH` to `hbench run`. The command and arguments use argv placeholders `${prompt}`, `${prompt_file}`, and `${workspace}`; no shell command is evaluated. Do not change `PATH` silently to work around a version mismatch. Every command after `hbench run` should use its printed run ID, especially after a retry.

`hb.study.v2` describes a public experiment over either an official `rodeo:slug@version` scenario or an immutable embedded `hb.task.v1` task derived from a local scenario. It can freeze personal setup metadata, local-skill content hashes, prompt treatments, enforcement assurance, and validated external adapters. Machine paths and secrets are omitted from the public contract. Bounded evaluator files, prerequisites, and lockfile-pinned fetch declarations are embedded so the downloaded contract retains the executable acceptance context. hbench keeps creator-side scenario and local-skill path mappings in a mode-0600 sidecar under `hb-out/studies`; losing that sidecar does not change the contract, but the original machine must supply matching local skill content before another run. Existing `hb.study.v1` contracts remain valid. The contract fixes the question, sources, comparison mode, scenario versions, setup arms, changed axes, repeats, random seed, judge protocol, win rule, and post-run stop thresholds. `controlled` studies reject undeclared setup differences. `ecological` studies compare complete real-world bundles and disclose their confounds.

Study execution is sequential by default. The seed randomizes the arm and scenario order. Each finished cell is saved under `hb-out/studies`, so the same command resumes after an interruption. `hbench study run` requires `--approve-spend`. Publishing is a separate command. If an older CLI forced a completed public-intent Study into private mode, `hbench study promote PRIVATE.yaml --out PUBLIC.yaml` creates a path-free v2 contract and verified source mapping without rerunning model cells. Publication revalidates each original binding and signs the projected public evidence.

Before any cell runs, hbench checks every scenario prerequisite. It reports missing or old tools and does not install them. If an uncached pinned repository, remote manifest, or lockfile-pinned dependency set is required, hbench prints one immutable fetch plan and asks for consent. Non-interactive agents must stop and give the user the printed `hbench fetch approve <digest>` command. A changed plan invalidates the prior approval.

The minute value is a live timeout. Token and dollar values are checked after each run because the supported harnesses do not expose a common live usage counter. A run can exceed a per-run threshold, and a study can exceed its total dollar threshold by one run. These values stop later runs; they are post-run thresholds, not billing-provider hard caps. The OCI `--max-usd` setting is a relay-enforced hard cap for each request.

A Callout adds a testable statement and attribution to one frozen study digest. A Challenge uses that exact digest. A changed setup, scenario, repeat count, budget, or judge rule is a linked counterexample instead of a title challenge. Callouts count distinct publishers rather than raw runs and report execution assurance separately from replication status. Conflicting winners are Contested; matching winners with metric variation are Mixed.

`hbench reproduce CALLOUT_URL` downloads the frozen Callout contract as a local YAML file. Validate it before any run.

The bundled `run-agent-rodeo-study` skill turns a natural-language request into either one direct ride or a comparison manifest. It shows the exact setup, matrix when applicable, and budget before it asks for approval. Install it only when requested with `hbench skill install`.

Version 0.7 runs Study matrices on the user's machine and publishes them as signed Open Range evidence. hbench signs the exact canonical `{run,snapshot}` envelope with a publisher key scoped to the Agent Rodeo origin. The site verifies the signature before persistence. The publisher previews the same payload that is uploaded. Raw agent logs remain local; a bounded 1 MiB `patch.diff`, judge results, setup identity, task contract, and telemetry disclosures may be published. The `controlled` comparison mode controls experimental axes; it does not grant the site's Controlled evidence badge. Only approved-runner attestations for an exact frozen cell can enter the official Rodeo Rating. Operators bind those runs before execution with `hbench controlled run --study STUDY.yaml --study-arm-id ARM --study-scenario-id rodeo:slug@version --study-repeat N`; hbench rejects a pack whose setup or per-run limits differ from the frozen arm. Controlled relays currently accept only enforceable JSON model endpoints; Cursor's streaming protocol is Open-only until equivalent model, output, and spend enforcement exists. Herdr can monitor an operator workflow, but it is never part of a measured setup unless the contract explicitly names it.
